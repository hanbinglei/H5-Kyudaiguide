修正机场指南三张照片的朝向

一、用户报告的问题

  「左边是办交通卡的地方」那张（step12）方向错了。
  根因：照片是上下颠倒的，所以画面里的左右也反了 ——
  阿遥说「左边是办卡的」，但倒过来的图上窗口在右边，文字也对不上。
  转 180° 后两个问题一起解决。

二、为什么会这样

  微信把 JPEG 的 EXIF 方向标记剥掉了，但传感器像素是原始朝向。
  本来靠 EXIF 告诉看图软件「要转 180°」的照片，脱掉 EXIF 之后
  就真的倒着显示了。这不是拍照拍反，是元数据丢失。
  → 解密流水线里应该考虑：微信 4.x 的 .dat 解出来就是没有 EXIF 的，
    后续处理不能假设方向正确。

三、全量排查结果（17 张里 3 张有问题）

  38 号 → 原始倒置 180° → 转 180° ✓
  42 号 → 原始就是正的 → 不需要转（我先误判转了 180°，已还原）
  45 号 → 原始转了 90°  → 转 -90°（顺时针 90°）✓
  其余 14 张 → 正常

四、判断方法上的教训（这部分比修图本身重要）

  用什么判据都试过，结论是：
  ✗ 拼图（多张缩略图放一起问）——**不可靠**。它把 38 号说成正常，
    而 38 号是全尺寸下能一眼看出倒置的。小图会让模型顺着答。
  ✗ 抽象提问「朝向正常吗」——四次回答互相矛盾，同一条信息
    能得到「正常」「倒置」「转了 90°」三种答案。
  ✗ Windows OCR 判朝向——对场景照（小字多）返回 0 行。
  ✓ **具体的位置关系**才可靠：「日文那一行在英文的上面还是下面？」
    「字符的头朝上还是朝下？」——日本车站标识是日文在上、英文在下，
    这个版式是硬约束，问出来三次答案都自洽。

  教训推广：问模型「对不对」不如问它「A 在 B 的哪一侧」。
  可验证的具体关系，比需要综合判断的抽象结论可靠得多。
