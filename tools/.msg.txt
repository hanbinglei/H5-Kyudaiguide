多语言查漏补缺：补 5 处绕过 t() 的硬编码

新增 tools/audit_i18n_full.py，查四类以前没人管的问题：
  A. JS 字符串字面量里的中日韩文字（排除 t() 参数与数据文件）
  B. index.html 静态文字是否被 JS 覆盖
  B2. aria-label / title / placeholder 里的中文（最隐蔽：看不见，静态也不报错）
  C. t(key, 兜底) 的兜底值是否与词典 zh 一致
  D. t() 用到的 key 是否四语齐全

修掉的 5 处：
  1. <title> 四语都停在中日混排 —— 全站从没有人设置 document.title
  2. 底栏 aria-label「主导航」
  3. 地图 iframe 的 title「校园地图」
  4. 村历翻月按钮 aria-label「上一月/下一月」（只有 ‹ › 符号，全靠它）
  5. 「支持这个项目」卡片不跟着切语言 —— 重建写在 if(!built) return 之后，
     面板没打开过就永远切不过来。和上次入口按钮文案是同一个坑，犯了第二次

排除的误报（写进工具的已知限制，避免下次重复排查）：
  · 底栏 5 个按钮 —— app.js:153 用动态拼 id 本地化，静态正则看不出
  · 村历的日文原名 —— #upcomingList 每行本来就有 row-t(译文)+row-ja(日文原名)，
    日文下少 3 个元素是译文与原名相同去重，是刻意设计
  · 「闪记」那一组是浏览器扩展注入的，不在仓库里

工具自身踩到的两个坑（都记进注释）：
  · 写临时文件后立刻交给 node 读，必须 with 显式关闭；否则缓冲区没落盘，
    node 读到空文件——表现为「文件存在、退出码 0、stdout 为空」，极难看出
  · node script.js A 里 argv[1] 是脚本自己，第一个参数在 argv[2]；
    写错会把脚本自身读进 vm 沙箱，报「require is not defined」，完全指错方向
